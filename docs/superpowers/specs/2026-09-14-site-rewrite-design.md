# Переписывание сайта prom-products.kz — дизайн

Дата: 2026-09-14
Статус: утверждён в брейншторме, ожидает вычитки спеки

## 1. Цель и границы

Сайт-каталог «Батыс Курылыс XXI» (гидравлический и трубный инструмент, Астана) пишется заново. Функции сохраняются:
каталог по категориям, карточка товара, корзина-запрос, заявка «имя + телефон» с сохранением в БД и письмом
администратору, контакты с WhatsApp. Добавляются: админка, отдельные SEO-страницы, количество в заявке,
переписанный уникальный контент.

Главная бизнес-цель — органический трафик из Google/Яндекс по запросам вида «<товар> <модель> купить Астана/Казахстан».
Попадание в топ не гарантируется кодом; спека покрывает техническое SEO и контент, внешние действия — в чек-листе (§12).

**Вне границ:** онлайн-оплата, личные кабинеты, казахская версия, поиск по сайту, блог (возможен позже),
очередь задач (Celery), публичный API.

### Проблемы текущей версии (причины переписывания)

- Пароль приложения Gmail закоммичен в `docker-compose.yml` (остаётся в истории git — **должен быть отозван**).
- `/admin/*`, `POST/PUT /products` без авторизации; через Caddy доступны снаружи по `/api/`.
- XSS: описание выводится через `dangerouslySetInnerHTML` без очистки.
- `entrypoint.sh` при каждом старте повторно вставляет категории: в БД 147 строк вместо 21.
- SPA из одной страницы, без URL у товаров — поисковики каталог не видят.
- В корзине нет количества; заявка хранится JSON-строкой; `node_modules` в git; адрес сервера в коде.
- Контент скопирован с сайта производителя вместе с inline-стилями, картинки грузятся с чужих доменов.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Стек | Django (монолит, серверные шаблоны) + Postgres 16 + лёгкий JS для корзины |
| Язык сайта | Только русский |
| URL | Английские slug |
| Цены | Скрыты по умолчанию; флаг `show_price` на товаре |
| Форма заявки | Имя + телефон; количество у каждой позиции |
| Уведомления | Email (SMTP) |
| Админка | Django admin, вход по паролю |
| Бренд | «Батыс Курылыс XXI» |
| Производитель | Не упоминается нигде (тексты, названия, разметка) |
| Хостинг | Тот же VPS, Docker Compose, существующий Caddy |
| Серверные команды | Выполняет владелец по инструкции |

## 3. Архитектура

```
config/                settings (django-environ), urls, wsgi
catalog/               Category, Product, ProductSpec, ProductImage, Redirect, SiteSettings; views, sitemap, admin
orders/                QuoteRequest, QuoteItem; форма, view, email, admin
templates/             base, home, catalog_index, category, product, quote, quote_thanks, contacts, 404
static/css/site.css    один файл, без CSS-фреймворка
static/js/cart.js      корзина, ~150 строк, без сборщика
content/catalog.yaml   переписанный контент (источник для импорта)
legacy/                снимок выгрузки старого сайта (categories.json, products.json), не меняется
deploy/                Caddyfile.example, backup.sh, DEPLOY.md
Dockerfile, compose.yml, .env.example, pyproject.toml + lock
```

Сервисы compose: `db` (postgres:16, без проброса порта наружу, volume `pgdata`), `web` (gunicorn, `127.0.0.1:8000`).
Статика — whitenoise. Медиа — volume `media/`, отдаётся Caddy напрямую.
`collectstatic` выполняется при сборке образа. При старте `web`: `migrate --noinput` → `createcachetable` → gunicorn. Никаких seed-скриптов при старте.

Зависимости: Django 5.x, psycopg 3, django-environ, gunicorn, whitenoise, Pillow, nh3, django-axes,
django-prose-editor, PyYAML; dev: pytest, pytest-django, ruff. Версии фиксируются lock-файлом.

## 4. Модель данных

**SiteSettings** (синглтон, редактируется в админке): `company_name`, `address`, `phones` (текст, по строке),
`whatsapp_numbers` (текст, по строке), `notification_email`, `public_email`, `working_hours`, `bin`, `map_url`.
Пустые поля не выводятся на сайте и в разметке. Начальные значения: адрес «Казахстан, г. Астана,
ул. Керей Жанибек хандар, 50/3», WhatsApp +7 777 305 4243 и +7 777 377 3763.

**Category**: `name`, `slug` (unique), `seo_text` (HTML, очищается), `meta_title`, `meta_description`,
`sort_order`, `is_active`.

**Product**: `category` (FK, PROTECT), `name`, `slug` (unique), `model_code`, `short_description`,
`description` (HTML, очищается `nh3` при сохранении), `price` (Decimal, null, ₸), `show_price` (bool, default False),
`is_active`, `sort_order`, `meta_title`, `meta_description`, `created_at`, `updated_at`.
При изменении `slug` у сохранённого товара или категории создаётся `Redirect(old_path → new_path)`.

**ProductSpec**: `product` (FK, CASCADE), `name`, `value`, `sort_order`.

**ProductImage**: `product` (FK, CASCADE), `image` (WebP, ≤1600 px по длинной стороне; миниатюра 400 px
генерируется при сохранении), `alt`, `sort_order`. Первое по `sort_order` — главное.

**Redirect**: `old_path` (unique), `new_path`. Middleware отдаёт 301 для 404-ответов, если путь найден.

**QuoteRequest**: `name`, `phone` (нормализован `+7XXXXXXXXXX`), `status` (`new` / `in_progress` / `closed`),
`admin_note`, `email_sent` (bool), `source_ip`, `created_at`.

**QuoteItem**: `request` (FK, CASCADE), `product` (FK, SET_NULL, null), `product_name` (снимок), `quantity` (1–999).

Очистка HTML (`nh3`), allowlist тегов: `p, br, strong, em, ul, ol, li, h2, h3, h4, a, table, thead, tbody, tr, th, td`;
атрибуты: только `href` у `a` (схемы http/https/tel/mailto). `style`, `class`, `font`, `img`, `script` удаляются.

### Каркас страниц (решение владельца, 2026-09-16)

Все публичные страницы строятся в трёхколоночной оболочке, как на старом сайте (макет `docs/design/mockup.html`):

- **Слева** — список категорий («Все товары» + активные категории), текущая подсвечена. При ширине < 1100 px меню скрыто и открывается кнопкой «Категории» как выезжающая панель.
- **По центру** — содержимое страницы. На главной товары сгруппированы по категориям (блок на категорию со ссылкой «Все»); у каждой карточки кнопка «В запрос».
- **Справа** — панель «Запрос КП» (список позиций с количеством, форма «имя + телефон», кнопка отправки) и контакты (адрес, кнопки WhatsApp). Закреплена при прокрутке на ≥ 1100 px; на узких экранах идёт после содержимого, сверху — кнопка «Запрос (N)».

Отдельные страницы категорий и товаров (для поиска) сохраняются. `/quote/` — адрес отправки формы и страница показа ошибок, `/quote/thanks/` — подтверждение.

Неактивные категории и товары отдают 404. Товар в неактивной категории — 404.
Старые пути `/api/*` не поддерживаются.

## 6. Корзина и заявка

**cart.js.** `localStorage["quote_cart"]` = массив `{id, name, url, thumb, qty}`. Повторное добавление увеличивает
`qty`. Счётчик позиций в шапке. `/quote/` рендерит список из `localStorage`; изменение количества и удаление
позиций на месте. При отправке формы позиции сериализуются `[{id, qty}]` в скрытое поле `items`. При пустой
корзине форма заблокирована. Без JS: страницы каталога работают, корзина недоступна, кнопка WhatsApp работает.

**Обработка POST `/quote/`:**
1. Honeypot-поле заполнено → ответ как при успехе, ничего не сохраняется.
2. Лимит: не более 5 успешных заявок в час с одного IP (Django cache) → ошибка формы «Слишком много заявок».
3. Валидация: имя 2–100 символов после trim; телефон — цифры после нормализации `8XXXXXXXXXX`/`7XXXXXXXXXX`/
   `+7XXXXXXXXXX`, а также 10 цифр, начинающихся с 7, → `+7XXXXXXXXXX`, иначе ошибка у поля; `items` — валидный JSON, 1–50 позиций,
   `qty` целое 1–999; позиции с неизвестными или неактивными `id` отбрасываются; если после этого пусто —
   ошибка «Корзина пуста или товары недоступны». Названия берутся из БД. Одинаковые `id` суммируются.
4. В одной транзакции создаются `QuoteRequest` и `QuoteItem`.
5. `transaction.on_commit`: письмо на `SiteSettings.notification_email` (fallback — env `ADMIN_EMAIL`),
   SMTP-таймаут 10 с. Тема «Заявка №<id> — <имя>»; тело: имя, телефон, позиции с количеством и ссылками,
   ссылка на заявку в админке. Успех → `email_sent=True`. Ошибка → лог уровня ERROR, `email_sent` остаётся False.
6. Редирект на `/quote/thanks/?id=<id>`; страница «спасибо» очищает корзину в `localStorage`.

## 7. Админка

- URL из env `ADMIN_URL` (не `admin/`). `django-axes`: блокировка после 5 неудачных попыток на 30 минут.
- Роли: суперпользователь; группа «Менеджер» — права на Category, Product (+ инлайны), QuoteRequest, Redirect, SiteSettings.
- **Product:** список — миниатюра, название, категория, `is_active`, `show_price`, `price`; фильтры категория/активность;
  поиск по `name`, `model_code`. Форма — `prepopulated_fields` для slug, редактор `django-prose-editor` для
  `description`, инлайны ProductSpec и ProductImage, подсказки длины meta (≤60 / ≤160).
- **Category:** аналогично, редактор для `seo_text`.
- **QuoteRequest:** список — дата, имя, телефон (`tel:`-ссылка), число позиций, `status` (list_editable), `email_sent`;
  фильтры статус/дата; сортировка по убыванию даты; позиции read-only инлайном; добавление запрещено.
- **SiteSettings:** одна запись, удаление запрещено.

## 8. SEO

- Уникальные `title` (по умолчанию `<Название> купить в Астане — Батыс Курылыс XXI`, переопределяется `meta_title`),
  `meta description`, один `h1`, canonical на каждой странице, `lang="ru"`.
- JSON-LD: `LocalBusiness` (главная, контакты; только непустые поля), `BreadcrumbList` (категория, товар),
  `Product` (name, image, description, sku = model_code; `offers` с ценой в KZT **только** при `show_price` и `price`).
  Поле `brand` не выводится.
- `sitemap.xml` с `lastmod`; `robots.txt` со ссылкой на sitemap и `Disallow: /quote/` (адрес админки в robots.txt не указывается, чтобы не раскрывать его).
- Open Graph (title, description, image).
- Производительность: WebP, `width/height` у изображений, `loading="lazy"` ниже первого экрана, один CSS и один JS,
  без внешних шрифтов (системный шрифт). Цель — Lighthouse Performance и SEO ≥ 90 на мобильном для страницы товара.
- `new.prom-products.kz` (стенд): `X-Robots-Tag: noindex` и basic-auth на уровне Caddy.

**Визуальный стиль:** mobile-first, сдержанный «промышленный» — нейтральный фон, один акцентный цвет,
крупные фото, характеристики таблицей. Перед вёрсткой шаблонов в плане есть шаг согласования макета главной и
карточки товара.

## 9. Контент и импорт

`python manage.py import_catalog` читает `content/catalog.yaml` и файлы изображений; идемпотентна
(`update_or_create` по slug, характеристики и изображения товара пересоздаются). Выводит отчёт: создано/обновлено,
не найденные изображения.

Подготовка `content/catalog.yaml` (выполняется в рамках реализации, результат вычитывается владельцем):

1. **Категории:** 147 строк → 21 по имени, slug из §5.
2. **Названия:** убрать переносы строк и двойные пробелы; заменить латинскую `c` на кириллическую `с`
   («cъемник» → «Съёмник»); удалить упоминания производителя («Электрический пресс ИНСТАН ПГГ-15ЭП» →
   «Электрический пресс ПГГ-15ЭП»).
3. **Дубли — предложение, окончательно решает владелец при вычитке `catalog.yaml`:**

   | Старые id | Товар | Предложение |
   |---|---|---|
   | 34, 44 | Съёмник СГ-5Н | Объединить |
   | 38, 43 | Съёмник СГ-10Н | Объединить |
   | 42, 48 | Съёмник СГ-20Н | Объединить |
   | 41, 47 | Съёмник СГ-30Н | Объединить |
   | 40, 46 | Съёмник СГ-50Н | Объединить |
   | 39, 45 | Съёмник СГ-100Н | Объединить |
   | 23, 24 | Домкраты ДА5–ДА30 / ДА5–ДА50 | Объединить в один товар (ДА5–ДА50) |
   | 26 | Серия «Съёмники СГ со встроенным и выносным насосом» | Удалить как товар; общий текст → SEO-текст категории |

   Итог — 50 товаров.
4. **Характеристики:** извлекаются из HTML-таблиц и списков исходного описания в `ProductSpec`. Числовые значения
   переносятся только из исходника; ничего не дополняется.
5. **Тексты:** для каждого товара — `short_description` (1–2 предложения), `description` (150–300 слов: назначение,
   особенности, применение, комплектация из исходника, поставка по Казахстану), `meta_title`, `meta_description`;
   для категорий — `seo_text` 100–200 слов; тексты главной и контактов. Деловой тон, без превосходных степеней,
   без упоминания производителя. Для товаров с пустым исходным описанием (9 шт.) — текст только по названию и
   характеристикам из названия, помечается в YAML `needs_review: true`.
6. **Изображения:** скачиваются `pic_url` и `<img>` из описаний → WebP в `content/images/<product-slug>/`.
   Отчёт: не скачавшиеся и те, где при просмотре виден логотип производителя (отмечаются вручную).
7. **Цены:** старые значения (вероятно, в рублях) не импортируются; `price = null`, `show_price = false`.
8. **Вычитка:** специалист по инструменту проверяет `catalog.yaml` до переключения домена. Это блокирующий шаг.

**Старые заявки:** при переключении владелец делает `pg_dump` старой БД; команда `import_legacy_requests <dump.sql>`
создаёт `QuoteRequest` со статусом `closed`, `email_sent=True`; позиции из JSON `product_list` группируются по `id`
(количество = число повторов), `product` сопоставляется через таблицу старых id → slug, `product_name` из JSON.

## 10. Безопасность

- `DEBUG=False`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, `SECURE_PROXY_SSL_HEADER`, `SESSION/CSRF_COOKIE_SECURE`,
  HSTS 1 год, `X-Content-Type-Options`, `Referrer-Policy`.
- Секреты только в `.env` на сервере; в репозитории `.env.example`. `.gitignore`: `.env`, `media/`, `node_modules/`,
  `__pycache__/`, `.venv/`, `staticfiles/`.
- HTML из админки проходит `nh3` (§4); шаблоны с автоэкранированием, `|safe` только для очищенных полей.
- Нет CORS и публичного API.
- Действие владельца вне кода: отозвать пароль приложения Gmail из старого `docker-compose.yml`, выпустить новый.

## 11. Тестирование

pytest + pytest-django, Postgres в compose для тестов.

- **Заявка:** валидная отправка создаёт заявку и позиции; неверный телефон; нормализация `8…`/`7…`/`+7…`;
  неизвестные и неактивные товары отбрасываются; пустой результат — ошибка; `qty` 0 и 1000 отклоняются;
  дубли `id` суммируются; honeypot не сохраняет; 6-я заявка за час с IP отклоняется; сбой SMTP — заявка сохранена,
  `email_sent=False`; успех — `email_sent=True`.
- **Каталог:** неактивные товар/категория → 404 и отсутствие в sitemap; смена slug создаёт Redirect и 301;
  очистка HTML удаляет `script`, `style`, `font`, `img`.
- **SEO:** страница товара содержит `title`, `description`, canonical, парсящийся JSON-LD `Product`; `offers`
  присутствует только при `show_price=True` и заданной цене; в разметке нет `brand`.
- **Импорт:** двойной запуск `import_catalog` не меняет количество записей; `import_legacy_requests` на фикстуре.
- **Корзина (ручной чек-лист):** добавление, повтор увеличивает qty, изменение/удаление, счётчик, отправка,
  очистка после «спасибо», мобильная ширина 360 px.
- `ruff check` без ошибок.

## 12. Деплой и переключение

Выполняет владелец по `deploy/DEPLOY.md` с готовыми командами.
